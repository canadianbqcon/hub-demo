# CLAUDE.md: dashboard/hub/clash/ (Clash of Clans village tracker)

Scoped rules for the clash module. Cross-module rules are in `dashboard/CLAUDE.md`.

- **What it is:** Hub module under Gaming (no tile of its own in `hub_modules.py`) that replaces Clash Ninja: villages, running upgrades, API data, layouts, war plans. Spec `docs/specs/2026-11-10-clash-hub-design.md` (vault), plan `docs/plans/2026-11-10-clash-hub.md`.
- **Store:** vault `data/clash.db`, nine STRICT tables (`helper` added by 002, `speedup` by 003; `account.position` by 004 orders the village tabs, a trigger puts a new village last; `PUT /clash/api/order {tags}` takes every tag once). A second village is added by pasting its export (the "+ Add village" button opens the same paste box), times as UTC ISO strings, children cascade from `account(tag)`. Migration `db/migrations/clash/001_init.sql`, applied with `python3 db/migrate.py up clash` from the repo root.
- **Timers:** `db.apply_due(conn, now)` is the only place a finished upgrade moves a count; it claims rows with `DELETE ... RETURNING` in one transaction. `start_upgrade` raises `FacilityFull` (builders = `account.builders`; lab and pet house cap at 1).
- **Tests:** from `dashboard/hub`, `python3 -m pytest clash -q`. `conftest.py` blocks the real `notify` package for every clash test (it writes `data/notify.db` and pushes to his phone); a test that wants a fake installs its own. Test schemas load every `db/migrations/clash/*.sql` up section in order.
- **Boosts and helpers (Check 2 send-back, 2026-11-10):** `db.speed_up(c, id, rate, now, kind=)` runs one timer at `rate`x for an hour. Each use is stored as a window in `speedup` (migration 003), and the finish is recomputed from the work left over all active windows: different kinds add their extra rates (potion plus bite is 11x), and a second of the same kind starts when the first ends (two potions = 10x for 2h). A typed-in finish time (`edit_finish`) clears the windows. `db.boost` applies it to every running timer of one facility. `POST /clash/api/boost {tag, kind}` with kinds in `api.BOOSTS` (Builder Potion 10x, Builder Bite 2x, Research Potion 24x, Study Soup 4x, Pet Potion 24x; effects add, so potion plus bite is 11x). `POST /clash/api/helper {tag, data_id, upgrade_id}` puts the Builder's Apprentice or Lab Assistant (level N works at N+1x) on one running timer, then steps `ready_at` to the next daily reset; the ready check and the write share one `BEGIN IMMEDIATE` so a double click applies it once. Both routes return 400 on a non-object body, a non-string tag or kind, or a bool or out-of-range id. An export `helper_cooldown` above 7 days is dropped (ready_at NULL), never a rejected paste. Helper levels come from the export's `helpers` into the `helper` table (migration 002); `api._HELPER_IDS` maps ids by hand because the package tags Prospector 93000002, but his export has 93000002 at level 5 (the Alchemist). The export's `boosts.builder_boost` (seconds left on a running builder boost) is not applied.
- **Level caps (2026-11-10):** every caller (paste, village page, plan, war pages, `unlock_th`) goes through `gamedata.max_level(id, th)`. Troops, spells, pets, equipment and buildings come from the package's `townHallRequired`. Heroes come from the package Hero Hall table, except at the top Town Hall, where the official API's hero `maxLevel` from any cached `/players/` body wins (0.19.1 says King and Queen 105, Warden 80 at TH18; the game says 110, 110, 85). The API's `maxLevel` is the overall max, not a Town Hall cap, so it says nothing below the top TH; for troops, spells, pets and equipment it matched the package at TH18, so they take no override. `coc_api.refresh` calls `gamedata.reload_api()` after a new player body. A paste never rejects a level above the cap (the game wrote it), only a level below 1 or a non-integer, and the village API reports `max` as at least the current level. Tests: `test_gamedata.py::test_hero_cap_follows_api_cache`, `test_export.py::test_king_above_bundled_cap_accepted`.
- **Upgrade queue (mark 2026-11-10 #5):** a wall tile's Start turns into Queue when every builder (or the lab, or the pet house) is busy. `queue_item` (migration 005) keeps the order per village; `db.schedule` places each item, in that order, on the lane of its facility that frees first (lane i = the i-th running timer by finish, as the timeline draws them). Routes: `POST /clash/api/queue {tag, data_id, from_level}`, `POST /clash/api/queue/remove {id}`, `PUT /clash/api/queue/order {tag, ids}` (every queued id once), and `/api/start` takes `queue_id` to take a started item off the queue. The village payload carries `queue` with lane, start and end. Timeline draws queued items as hatched bars; drag one onto another to take its slot (Earlier and Later in its panel are the touch path). When the lane frees, the bar turns into Start and a Hub reminder (`notify_glue.queued`, key `clash:q:<id>`, due at the planned start) tells him; it never assumes he started it in game. An item whose level no longer has a copy is dropped on the next read. Reminders are posted after the clash transaction commits, and `village()` commits right after `apply_due`: holding the write lock through the 1-3 s read made overlapping polls fail with "database is locked" (2026-11-10). Tests: `python3 -m pytest clash/test_queue.py -q`.
- **Supercharges and crafted modules (2026-11-11):** `gamedata._supercharge` renumbers levels flagged `supercharge: true` to base+1, base+2 on the same structure and stores `sc_base` (last normal level), so timers, queue, plan and caps run unchanged; `api.village()` sends `sc_base` on structures, upgrades and queue, and clash.jsx labels levels above it `base +SCn` (tile: normal level badge plus an `SC done/available` badge). `gamedata._modules` makes each crafted-defense module its own entity (category `crafted-module`, dataId = module dataId, icon = parent defense, every level gated at TH18 `CRAFTED_TH`), shown in the Crafted group. Export supercharge key is assumed `supercharge: n` on the building record (lvl + n): unverified, no export with a supercharge seen yet; check it on the first one.
- **Speed (2026-11-11):** never stat or read a gamedata or icon file per request; `/mnt/c` makes each stat ~13 ms. `gamedata._icons()` lists the icon folder once (cached, cleared by `reload()`), `api._helper_data` caches helper JSON, and `gamedata.warm()` (called from app.py at start) loads the package in the background. `gamedata.icon()` / `icon_file()` return `i-x.png?v=<mtime>`, which app.py serves as immutable, so a repeat page open fetches 1 icon instead of 125. Measured: `/clash/api/village` 5.4 s -> 0.14 s, repeat open tiles visible ~0.4-0.7 s.
- **Wall tiers:** each structure's `next` carries cost, resource, time and `th` = `gamedata.unlock_th(id, level+1)`, the lowest Town Hall whose cap reaches that level. The page groups by current TH, TH-1, TH-2, TH-3 and below, and Maxed, or by category.
- **Onboarding decision:** [[wiki/decisions/onboard-clash]].

## Export format (answers to the spec's seven gate questions, from his real export 2026-11-10, fixture `fixtures/export-real.json`)

1. **`data`** is the package `dataId` for every gameplay category (buildings, traps, units, siege_machines, heroes, spells, pets, equipment, helpers, guardians, builder base). Decos, obstacles, house_parts, skins and sceneries are cosmetic and not in the package: counted as known cosmetic, never as unknown.
2. **`timer`** is seconds remaining at the export `timestamp`; an upgrade ends at `timestamp + timer`.
3. **`lvl`** during an upgrade is the CURRENT level (the official API agrees); the timer ends at `lvl + 1`, so the upgrade row has `from_level = lvl`.
4. **`cnt`** is the number of copies at that level; absent `cnt` means 1.
5. **Repeats and walls** are one record per level (walls: 198 at 15 plus 127 at 16). Odd shapes: a Mortar record with `gear_up: 1` and no `cnt` (a geared-up copy, stored under its own level with cnt 1); Crafting Station (1000097) carries nested `types` each with `modules`; every module is applied as its own structure under its module dataId (102000033-41).
6. **`timestamp`** is unix seconds, UTC. The export carries no Town Hall field: TH is the level of the Town Hall record (1000001) in `buildings`.
7. **Timers** appear in heroes (facility builder), units, spells and siege_machines (lab), pets (pet_house), and in buildings and traps (builder). `buildings2`, `traps2`, `heroes2`, `units2` are builder base, out of scope.

Known-unused (listed, not skipped): `guardians`, `helper_recurrent`, `boosts`, every `*2` builder-base category. Builder count is not in the export: `account.builders` is set to max(2, builder timers) only when the account is created. `export.apply` is the only paste path (`POST /clash/api/paste`); tests: `python3 -m pytest clash/test_export.py -q`.

## Plan and layouts pages

- Routes live in `plan_pages.py` (attached to `api.bp`; `api.py` must import it at the bottom). Pages `/clash/plan`, `/clash/layouts`; `GET /clash/api/plan?tag=&have={"Gold":n}`; `GET|POST|PUT|DELETE /clash/api/layouts` (POST and PUT are multipart).
- Layout images: `<db folder>/clash/layouts/<uuid4 hex>.<png|jpg|webp>`, type read from magic bytes, 10 MB cap, deleted with the row; the img route 404s any name not matching that pattern. Tests: `python3 -m pytest clash/test_plan_pages.py -q`.

## Profile and war

- `war_pages.py` holds `/clash/profile`, `/clash/war`, `/clash/api/{profile,war,war-plan,refresh}`; it joins `api.bp` via `from . import war_pages` at the bottom of `api.py`. Pages: `frontend/{profile,war}.html`, JSX `static/{wp-common,profile,war}.jsx`, styles `static/war.css`. Tests: `python3 -m pytest clash/test_war_pages.py -q`.
- Banner is derived from `api_cache` (no key from `coc_api._key()`; 403 on the player path is `invalid_ip` when `last_error` is `accessDenied.invalidIp`, else `refused`). The stored banner has no IP; the Refresh answer carries it and wins. Data age is the cached `ok_at`. 404 on war is `not_in_war` / "War log private", never an error.
- `war_plan.attacker_tag` is a foreign key to `account`, so a plan row can only exist for a tracked account, not for any clan member. A plan target missing from the current enemy roster is returned with `gone: true`.

## Patch page

- `/clash/patch`: three tabs (Patch, Blog, Leaks), `static/patch.{jsx,css}`, CSS scoped under `.px`. Routes in `patch_pages.py` (joins `api.bp` from the bottom import of `api.py`): `GET /clash/api/patch[?before=]` (newest 50 sorted balance/update posts as `patch.post_view`, 50 blog rows, 90 leaks, the three `patch_fetch` rows, unsorted/failed counts, `blog_total`, `backfill_done`), `POST /clash/api/patch/refresh` (runs `patch.run` in the request, 409 while `.pending/clash-patch.lock` is held).
- Tables (migration `006_patch.sql`): `blog_post`, `patch_change` (`section`, `unit`, `of_name`), `patch_note` (intro, reason, watching), `leak_post`, `patch_fetch` (one row per source: blog, leaks, classify; `blog.backfill_page` NULL means the archive is complete).
- Job `clash-patch`, daily 07:00, in `scheduler.py` `PYTHON_JOBS` under `_locked_run` with the same lock file. Fetch is stdlib `urllib` with a browser User-Agent (curl gets Reddit's block page). The blog index puts each post's date before its link; pair them in page order. Supercell answers 404 past the archive's last page: only that ends the walk or the backfill; a page that loads but parses empty is an error (layout change). Backfill starts at page 4, and restarts there whenever the walk meets no stored post. Leak times are stored as UTC `db.FMT`; cards with no id or timestamp are skipped.
- Classify: up to 5 pending posts per run, one `claude-haiku-5-5` call each with thinking disabled (with thinking on it spent all 2,000 tokens and stopped). The model only picks block numbers and labels; stored text is always the block's own. `"Unit: change"` lines keep the part after the colon; `"Unit - text"` lines split into first sentence (change) and the rest (reason note). `validate` rejects bad labels but drops two harmless slips (a second change on a used block, a note on a change block). Two failures mark a post `failed`. A try is spent on a rejected answer, a per-request API error, or a 404/410 post page; an API outage (5xx, 429, 401/403, connection) stops the run and spends none. A line break inside a block keeps a space.
- Icons: `patch.icon_for` tries the unit's own `i-<slug>.png`, then its owner (`of_name`), through the cached `gamedata.icon_file` (never a stat per entry). Links and images only on the host allowlist `patch.HOSTS`.
- Tests: `python3 -m pytest clash/test_patch.py -q` (saved fixtures `fixtures/blog-*.html`, `leaks-new.html`; fake client; never the network).
